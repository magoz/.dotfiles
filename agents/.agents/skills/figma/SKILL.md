# Figma workflow router

Use this as the single entry point for Figma work. The detailed workflows remain in hidden leaf skills so they can stay close to Figma's official upstream package.

## Required procedure

1. Classify the task with the routing table below.
2. **Read every required leaf `SKILL.md` before calling the corresponding Figma MCP tool.** Loading this router alone does not replace a leaf's mandatory safety instructions.
3. Follow the leaf workflow and load only the references it requests. Do not read the entire Figma corpus.
4. When a task crosses boundaries, read all applicable leaves before acting.
5. Preserve the leaf names required by their `skillNames` logging instructions. The umbrella name `figma` does not replace those names.

## Combination rules

- `use_figma` always requires `figma-use`, even when another specialized leaf is also loaded.
- Figma-to-SwiftUI also requires `figma-design-to-code` before `get_design_context`.
- SwiftUI-to-Figma requires `figma-use`; add `figma-generate-design` for full screens or `figma-generate-library` for reusable components.
- Motion returned during design-to-code requires both `figma-design-to-code` and `figma-implement-motion`.
- Creating a file and then populating it requires `figma-create-new-file` first, followed by the relevant canvas leaves.

## Maintenance boundary

The nested `skills/figma-*` directories are vendored implementation details. Keep this router locally authored, preserve `disable-model-invocation: true` on every leaf, and reapply that flag after future upstream synchronizations.
